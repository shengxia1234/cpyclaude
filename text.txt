在 Linux 服务器上跑深度学习任务时，我们经常需要查看 GPU 的占用情况。最常用的命令通常是：
nvidia-smi
不过，nvidia-smi 更适合快速查看一次状态。任务较多时，如果想要持续观察显存占用、GPU 利用率以及具体进程，反复执行命令并不算方便。

最近发现了一个很好用的命令行工具：nvitop。

它可以理解为 GPU 版本的 top 或 htop。运行后，终端界面会持续刷新，直观展示每张 NVIDIA GPU 的利用率、显存占用、温度、功耗，以及各个进程的 PID、用户名和显存使用量等信息。

安装
使用 pip 安装：

pip install -U nvitop
也可以使用 conda：

conda install -c conda-forge nvitop
基本用法
安装完成后，直接运行：

nvitop
即可进入实时监控界面。

如果终端窗口较大，希望尽可能完整地显示 GPU 状态、进程信息和历史变化曲线，可以使用：

nvitop -m full --colorful
其中：

-m full 表示使用完整显示模式；
--colorful 会显示更加直观的渐变色图表。
这是我比较推荐的日常使用方式。

如果终端窗口较小，例如通过 SSH 连接服务器时，也可以使用更紧凑的界面：

nvitop -m compact
几个实用命令
只查看一次 GPU 状态，不进入动态刷新界面：

nvitop -1
这个用法类似于 nvidia-smi，但展示的信息更加清晰。

只查看指定的 GPU，例如 GPU 0 和 GPU 1：

nvitop -o 0 1
只显示当前环境变量 CUDA_VISIBLE_DEVICES 中可见的 GPU：

nvitop -ov
训练模型前如果已经设置了：

export CUDA_VISIBLE_DEVICES=2,3
再运行：

nvitop -ov
就只会显示当前任务可见的 GPU，避免被服务器上的其他显卡干扰。

修改进程状态的刷新间隔，例如每秒刷新一次：

nvitop --interval 1
如果只想监控，不希望误操作结束进程，可以使用只读模式：

nvitop --readonly
终端不支持 Unicode 字符时，可以切换为纯 ASCII 显示：

nvitop -U
交互式操作
进入 nvitop 界面后，还可以直接使用快捷键切换显示模式：

按 f：切换到完整模式；
按 c：切换到紧凑模式；
按 a：根据终端窗口大小自动选择显示模式；
按 t：查看 GPU 进程树；
按 q：退出。
在多人共享服务器时，进程树功能比较实用。它可以帮助我们判断某个 GPU 进程由哪个训练脚本启动，以及是否存在遗留的子进程。

nvitop 还支持向进程发送中断、终止或强制结束信号。不过，在共享服务器上操作时需要谨慎，最好先确认 PID 和用户名，避免误结束其他人的任务。

总结
相比于反复执行：

watch -n 1 nvidia-smi
nvitop 的界面更加直观，信息也更加丰富。对于经常使用 Linux 服务器训练模型的人来说，它是一个安装简单、上手成本很低，但能明显提升使用体验的小工具。

平时直接记住这一条命令，基本就够用了：

nvitop -m full --colorful
